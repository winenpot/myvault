(<- CURRENT marker lives on the task heading)

Goal: one encrypted KeePassXC database (.kdbx), built-from-source KeePassXC 2.8.0 on
laptop and on atpg (same .deb on both = identical), atpg holds the canonical copy,
laptop and Android phone sync to it over SSH/SFTP. No new open ports.

Architecture:
- KeePassXC has no server mode. "Server" = atpg stores the canonical .kdbx in an
  SFTP-only chroot for a dedicated `vault` user, plus daily versioned backups.
- Laptop: `scripts/vault-sync.sh` = download remote -> `keepassxc-cli merge` into
  local -> upload only if remote unchanged since download (else retry). KDBX merge
  is entry-level with history, so edits on both sides survive.
- Phone: Keepass2Android (has built-in SFTP + key auth + merge-on-conflict) opens
  sftp://vault@atpg/data/passwords.kdbx directly.
- Same binary everywhere: build once locally (INSTALL.md, tag `latest` = 2.8.0),
  package with `cpack -G DEB`, install the same .deb on laptop and atpg.

Decisions (user, 2026-10-31): sync = SSH/SFTP; server = atpg (Ubuntu 26.04, same as
laptop); phone = Android; KeePassXC built from source.

Config: one `.env` (documented in `.env.example`): VAULT_LOCAL, VAULT_REMOTE_HOST,
VAULT_REMOTE_PATH. Database master password is chosen and typed only by the user —
never stored in the repo, .env, scripts or chat. Sync script reads it via the
keepassxc-cli prompt (or KEEPASSXC secret from the desktop keyring later, optional).

Never commit: *.kdbx, *.key/*.keyx, .env, build output, upstream source.

### T7: `vault` SFTP-only user on atpg
Why: phone/laptop keys get file access only — no shell on the box.
- useradd -r -M -s /usr/sbin/nologin vault; /srv/vault (root:root 755, chroot),
  /srv/vault/data (vault:vault 700); /srv/vault/.ssh/authorized_keys
- /etc/ssh/sshd_config.d/50-vault.conf:
  Match User vault / ChrootDirectory /srv/vault / ForceCommand internal-sftp /
  PasswordAuthentication no / AuthorizedKeysFile /srv/vault/.ssh/authorized_keys /
  AllowTcpForwarding no / X11Forwarding no
- `sshd -t` before reload; keep the current session open while testing.
- Laptop: dedicated key ~/.ssh/vault_ed25519; `Host atpg-vault` in ~/.ssh/config.
Done when: `sftp atpg-vault` lists /data; `ssh atpg-vault` gets refused shell;
password login for vault refused.
Rollback: rm 50-vault.conf, reload sshd, userdel vault.

### T8: scripts/vault-sync.sh (+ tests with throwaway DBs)
Why: two-writer safe sync laptop<->atpg.
Flow: lock (flock) -> sftp get remote to tmp (if none: first push) -> keepassxc-cli merge
local tmp-remote (remote entries into local) -> record remote
mtime+size+sha -> re-stat remote; if changed, loop (max 3) -> put to data/.passwords.kdbx.tmp
-> sftp rename over data/passwords.kdbx (atomic) -> local backup kept in ~/Vault/.bak/ (last 20).
Modes: --dry-run, --check.
Tests (tests/test_sync.sh, bats-free plain bash): fake remote = local dir via
VAULT_REMOTE_HOST=local; cases: first push; remote-only edit pulled; both-sides edits
merged; remote changed mid-sync -> retry. Test DBs created with throwaway password via
`keepassxc-cli db-create -p` (test-only secret, never the real one).
Done when: tests pass; real sync run twice is a no-op the second time.
Rollback: delete remote file; local copy remains authoritative.

### T9: Server-side versioned backups
Why: SFTP overwrite by a buggy client must be recoverable.
Root systemd timer on atpg, daily: cp -a data/passwords.kdbx to /srv/vault-backups/YYYY-MM-DD.kdbx
(outside chroot, root 700), keep 60 days; check KDBX magic bytes (03d9a29a) before keeping.
Done when: `systemctl list-timers vault-backup.timer` shows next run and a manual run creates a file.
Rollback: disable timer.

Done when: all three test cases pass; offline phone still opens cached copy.

### T12 (wrap-up): docs/vault/ notes (Overview, Builds, Findings, Recovery), link from

Risks / notes:
- atpg sshd has PasswordAuthentication yes globally — not changed by this plan, but the
  vault Match block forces key-only for `vault`. Worth a separate hardening task.
- Simultaneous phone + laptop writes in the same second: the re-stat check narrows but
  can't fully close the window; backups (T9) + KDBX history cover it.
- Updating KeePassXC later: re-run T1 (git pull, checkout latest) -> T3 -> T4 -> T6.
